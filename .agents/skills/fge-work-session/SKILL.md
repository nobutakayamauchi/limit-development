# FOUNDRY GROWTH ENGINE — work session

Formal product name: **FOUNDRY GROWTH ENGINE**  
Nickname: **仕事してください。**

Use the existing deterministic executor instead of inventing provider-specific persistence logic:

```text
python foundry-growth-engine/scripts/day_session.py ...
```

The durable contract is `fge.work-record/v0`.

## Hard boundaries

- `AI CHAT != DURABLE MEMORY`.
- Never say `保存しました` unless the executor returns `status = COMMITTED` and a non-empty `commit_sha`.
- `SOURCE SEALED != PUBLICATION APPROVED`.
- Never publish UPDATE / ARTICLE / JOURNAL / SNS from a DAY SESSION command. Public release remains a separate human Review Gate: `投稿 / 修正 / 記録だけ`.
- Never force confidential or private raw work into a public Git repository. If the current ledger is public and the material is not explicitly public-safe, use an authorized private work ledger or report that durable save cannot safely complete yet.
- Do not create a native app, MCP server, new database, scheduler, or media service just to satisfy these commands.
- NAGI + salvaged Vlog media capture is an optional field-input route, not the standard path.

## Determine the target ledger

Prefer the Git repository that owns the current work when the raw record is safe for that repository.

For sensitive work, use an authorized private Git work ledger. The same FGE Work Record protocol applies.

Do not use provider chat history as the only copy.

## Command mapping

### 「ここまで保存」

Persist only the material since the previous durable checkpoint where possible.

Run:

```bash
python foundry-growth-engine/scripts/day_session.py checkpoint \
  --repo <ledger-repo> \
  --project "<project>" \
  --summary "<delta summary>" \
  --source-adapter codex \
  --commit
```

Add `--evidence-ref`, `--media-ref`, `--change`, `--why`, `--result`, `--next-action`, or `--open-loop` only when they preserve real information. Do not invent missing evidence.

If the user explicitly says record only, add:

```text
--intent RECORD_ONLY
```

Success response, after reading the JSON receipt:

```text
保存しました。
commit: <commit_sha>
セッションは継続中です。
```

If the executor returns `LOCAL_ONLY`, a non-zero exit, or no commit SHA, do **not** use that success wording.

### 「これ一本」

Persist the current delta and force an ARTICLE candidate while keeping the session open.

Run:

```bash
python foundry-growth-engine/scripts/day_session.py article \
  --repo <ledger-repo> \
  --project "<project>" \
  --summary "<article-worthy delta>" \
  --source-adapter codex \
  --article-instruction "<user instruction if any>" \
  --commit
```

Do not close the DAY SESSION. The same source item may later be referenced briefly by the daily JOURNAL; do not duplicate a second full article.

### 「今日は終わり」

Persist the final remaining delta and seal the source session.

Run:

```bash
python foundry-growth-engine/scripts/day_session.py end-day \
  --repo <ledger-repo> \
  --project "<project>" \
  --summary "<final delta / day close>" \
  --source-adapter codex \
  --commit
```

Before sealing, verify that required photos/audio/video/evidence are not available only inside the chat. If media is still incomplete, do not seal.

A successful `END_DAY` receipt must report:

```text
status = COMMITTED
session_state = SEALED
commit_sha = non-empty
```

After that, public REVIEW candidates can be regenerated by FGE, but publication still requires the separate human Review Gate.

## Session ID behavior

The executor automatically uses a day/project session ID when `--session` is omitted and auto-increments `session_sequence`.

If the operator already established an explicit session ID, keep using it with `--session <id>`.

Never reopen a SEALED session. Start a new session instead.

## Media

Large media does not need to live in Git. Use durable `--media-ref` values.

When supplied media is durably referenced/persisted, use the matching state. Never pass `INCOMPLETE` to `end-day`; the executor will reject the seal.

## Output discipline

The executor's JSON is the Save Receipt source of truth. Report the receipt, not an optimistic guess.
