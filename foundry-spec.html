DEVELOPMENT SPEC

ほんまに、スマホ1台です。

職場？ ポッケの中。

スマホで全部のコードを手打ちする、という意味ではありません。スマホを指令所にして、AI・GitHub・クラウドへ仕事を渡し、結果を確認して次の指示を出します。

GitHubを見るトップへ戻る

スマホは「作業机」ではなく「指令所」

スマホで指示・確認→AI / GitHub / Cloud が実行

設計、調査、コード変更、テスト、記録、公開。重い処理は外へ逃がし、スマホでは判断と指示に集中します。

基本の流れ

01 THINKスマホで相談・方針決め。
02 BUILDAI/Agentへ実装を渡す。
03 VERIFYGitHub・テスト・証拠で確認。
04 PUBLISH必要なものだけ公開。

使っている役割

スマホ

会話、指示、確認、承認。どこにいても仕事へ戻る入口。

AI

調査、設計補助、実装、レビュー、文章作成。役割ごとに使い分ける。

Git / GitHub

コード、履歴、Issue、PR、証拠。仕事の正本を残す場所。

Cloud

ビルド、テスト、サーバ処理、公開。スマホに重い仕事を背負わせない。

なぜこれで作れる？

「スマホだから小さいことしかできない」ではなく、「スマホで全部処理しようとしない」からです。

必要な能力を外部へつなぎ、判断だけを手元へ戻す。ONE PHONE FOUNDRYは、この分業を前提にしています。

総てはポッケのなかにある。

実際の制作物と開発記録はトップとGitHubから確認できます。
