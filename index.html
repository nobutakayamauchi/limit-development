WHAT IS LIMIT DEVELOPMENT?

何をやっている人なのか。

面倒・詰まり・繰り返し作業を見つけたら、AIと既存資源を使って最小の仕組みにする。そして自分で使い、現実で壊し、残す価値があるものだけを公開する。

NOW / CURRENT WORK

いま、何を作っているか。

開発そのものだけでなく、開発を届ける・記録する・仕事に変える部分まで、自分の面倒から仕組みを生やしている。

CURRENT SERVICE / BRIDGEPATCH

毎週残る面倒を、一工程だけ切る。

本格システムを入れるほどではない。でも毎回同じ作業が痛い。そんな業務を全部作り替えず、一工程だけ小さく直す。

まず無料で制作可否を確認。高リスク業務は対象外または個別審査。

BridgePatchを見る
PUBLICATION TOOL / X ARTICLE ENGINE

投稿が面倒になったので、記事化する仕組みを作った。

開発記録をX向けの記事へ変換し、Evidence checkを通し、最後の公開判断だけは人間に残す。

自動化しても、最終投稿権限までは機械に渡さない。

X Article Engineを見る
DOGFOODING

自分で作って、自分で踏んで、自分で壊す。

デモが動いただけでは完成にしない。自分の実際の開発・生活フローに入れて、壊れ方まで観測する。

BUILD

欲しいから作る

動画編集、デバッグ、記録、投稿。最初の要求はだいたい自分の「面倒くさい」から始まる。

USE

最初のユーザーは自分

自分の実運用へ投入し、想定外操作や現実の負荷に当てる。

BREAK

自分のシステムを守らない

壊れたら隠さず、原因・誤判定・失敗したテストまで次の判断材料にする。

SURVIVE
