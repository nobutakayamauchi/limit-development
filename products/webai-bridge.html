WEB AI BRIDGE / PRODUCT

WebAI Bridge

AIを作った。
次に困るのは「どう売って、どう渡すか」です。

GPTs、Skills、普通のWeb実装。どれも使えます。でも「AIを商品として売る」ところまで考えると、それぞれ別の弱点が残ります。WebAI Bridgeは、その残った面倒をまとめて持つための配布・販売基盤です。

4方式を比較する実装をGitHubで見る

FIRST / GPTs

まずGPTs。
便利。でも、Web商品そのものではありません。

GPTsは今も作成・共有できます。ただし、OpenAI自身が「GPTsはChatGPTの中で使うもの」で、外部サイトへ埋め込む用途ではないと案内しています。購入者はChatGPTへ入り、そこで使う形です。

GPTsが悪いわけではありません。
「販売するWeb商品」にしたい時、境界がChatGPT側にある。

リンク共有はできる。でも自分のサイトそのものとして届けるわけではない。

決済、利用権、失効、推論代の設計まで自分の商品側で握りたいなら、別の仕組みが必要になります。

SECOND / SKILLS

じゃあSkillsを配る？
強い。でも「配る商品」としては癖があります。

Skillsは指示、例、コード、補助ファイルを含められる再利用ワークフローです。OpenAIのAgent Skills標準に沿って持ち運べるのは強みです。一方で、Personal Skillsは主にBusiness / Enterprise / Healthcare / Edu向けで、Web・デスクトップ・モバイル間も自動同期ではありません。

ENVIRONMENT

購入者環境に依存

プラン、ワークスペース設定、対応面、インストール可否などの条件が入ります。

INSTALL

「URLだけ」ではない

Skillを追加・インストールして使う前提。Webを開くだけ、とは違います。

PACKAGE

中身を渡す方向

Instructionsやコードを含むSkill自体を配るため、販売ノウハウをサーバ側だけに置く設計とは別物です。

COMMERCE

販売機構は別

決済、購入者限定、失効、推論代の回収は別途設計が必要です。

THIRD / PLAIN WEB

じゃあ全部Webへ逃がす。
自由。でも、今度はWebサービスを1個作ることになります。

ここまで来ると自由度は一気に上がります。購入者はURLを開けばいい。ChatGPTの特定プランにも依存しにくい。中身もサーバ側に置けます。ただし、その瞬間からAIではなく「商用Webサービス」の仕事が始まります。

AUTH

認証

誰が購入者なのか。別端末ではどうするか。セッションはどう守るか。

PAYMENT

決済

Stripe等の決済、Webhook、購入状態との紐付け。

ENTITLEMENT

利用権

買った人だけ開く。返金・失効したら止める。URLをコピーされても守る。

INFERENCE

推論代

販売者負担かBYOKか。APIキーをどう扱い、予算超過をどう止めるか。

WHY BRIDGE

Bridgeの違いは、
「Webに逃がす」だけじゃない。

普通のWeb

自由になる代わりに、全部自分で作る。

AI画面を作っただけでは商品になりません。決済、購入者判定、利用権、失効、BYOK、Knowledge、Webhook、秘密情報、デプロイまで残ります。

WebAI Bridge

その「残り」を最初から共通基盤にする。

AI Package、Access、Inference Payer、Deliveryを分離し、商品ごとに毎回同じ商用基盤を作り直さないためのBridgeです。

PROOF

「できるはず」ではなく、
商用チェーンを実機で殴っています。

固定ドメイン + iPhone + Stripeで実証

Creator Studioから商品を公開し、実決済、購入者への利用権付与、BYOK、サーバ側Knowledge、モデル応答、失効後の即時拒否まで、一連のチェーンを実機で通しています。

Creator Studio → Publish → Stripe Payment → Entitlement → iPhone Buyer → BYOK → Knowledge → Model → Revoke → Denied
まだ「万能完成品」とは言いません。

現行リポジトリはHosted v1候補です。最新版headの固定ドメイン再検証など、リリース前の確認項目も明示しています。

THE SHORT VERSION

GPTsで足りるなら、GPTsでいい。
Skillsで足りるなら、Skillsでいい。

でも「購入者はURLを開くだけ」「AIの中身は手元に残す」「決済と利用権をつなぐ」「推論代の支払者も分ける」「止めたい時は止める」まで欲しくなったら、普通のWeb開発が一気に重くなります。

その重いところを、毎回作らなくていいようにするのが WebAI Bridge です。
